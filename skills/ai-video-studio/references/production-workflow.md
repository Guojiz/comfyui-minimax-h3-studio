# 生产工作流

> 何时加载：需要按完整生产流程做一条片子（广告/种草/短片/品牌片/短剧片段等），或用户要求“认真做/按流程来”，而不是一句话快速出片时，加载本文档。

## 定位

本文档是默认生产路径。一句话出片（三段式快速路径：提示词增强 → 首帧生图 → 视频生成）只是第 6 步的一种执行捷径，不再代表完整流程。

四大核心分工：

| 核心 | 职责 |
| --- | --- |
| Agent | 创意编排与决策者：推进阶段、产出清单、在决策点请求确认 |
| Skill | 可复用知识/流程：让生产步骤稳定复现 |
| 资产 | 角色/场景/风格/道具/参考等可复用素材，跨项目优先复用 |
| ComfyUI | 操作面/执行面/技术工作流画布，本技能驱动本机 `http://127.0.0.1:8188` |

## 0. 简报

**目标**：生成任何内容前，把需求锁成可核对的清单。

Agent 产出 brief 清单，缺项先问、不猜：

- 目标人群与核心诉求
- 平台与画幅（9:16 / 16:9 / 21:9 / 1:1 / 3:4 / 4:3）
- 目标时长（超过 15 秒进入 `references/long-video.md`）
- 用途（投放 / 种草 / 品牌 / 短剧 / MV）
- 风格方向与参考
- 必须出现 / 禁止出现的内容
- 已提供素材（图片 / 视频 / 音频 / 文档）
- 预算与授权（音乐、人物肖像、品牌素材）

**确认点**：brief 逐项打勾；没有确认前不进入调研。

确认后初始化项目目录；已有项目直接复用，不要覆盖：

```bash
bash skills/ai-video-studio/scripts/init-project.sh <项目目录> --name "项目名称" [--git]
```

## 1. 调研与创意

**目标**：需求驱动调研，产出有依据的创意，不盲目造词。

- 围绕 brief 的关键词做趋势 / 参考 / 竞品调研
- 参考与证据保存到项目 `references/`，记录来源、日期、为什么相关
- 只把证据可支持的结论写进创意；找不到证据的“潮流词”不写
- 调研产出可以是趋势摘要、参考图、参考结构笔记

**决策点**：判断调研是否回答了 brief 的未知项；没回答就继续补调研，不带着疑问进入创意。

## 2. 创意方向锁定

**目标**：把创意收敛成一句话，并形成风格卡。

Agent 产出：

- 一句话核心创意：主体 + 地点 + 事件 + 题材风格 [+ 特殊运镜]
- 风格卡：色彩 / 光影 / 介质 / 节奏

示例骨架：

```
主体（一位穿白色厨师服的咖啡师）在（清晨街角咖啡车）做（拉花特写），
（写实生活方式广告，暖调晨光，轻微手持质感，节奏先慢后快）。
```

**确认点**：核心创意与风格卡经用户确认后才继续；方向不定，后面所有资产和提示词都会返工。

## 3. 资产准备

**目标**：按 `references/asset-management.md` 收集、校验、登记资产；新项目优先复用资产中心。

- 列出本片需要的角色 / 场景 / 风格 / 道具 / 参考资产
- 先在资产中心找可复用资产，找不到再新建
- 每个资产登记：名称、分类、外观描述、来源路径、授权状态
- 校验规格：图片 JPG/JPEG/PNG/WEBP/HEIC/HEIF 且单文件 ≤30MB；视频 H.264/H.265 且 ≤50MB；音频 WAV/MP3 且 ≤15MB
- 默认打包节点未实现素材上传，登记仍要做：资产用于描述一致性与未来参考能力；
  若本机 ComfyUI 已加载支持上传的扩展节点，按该工作流实际能力执行

**决策点**：资产是否齐、是否可复用；缺资产列出缺口并决定补做或调整创意。

## 4. 剧本与分镜

**目标**：把创意变成脚本和 shot 列表。

- 脚本：谁、在哪、做什么、说什么、情绪怎么变化
- shot 列表每行写齐：景别 + 内容 + 运镜 + 动作 + 台词 + 音效
- 台词预算：中文 3–4 字/秒（5 秒 ≤18 字、10 秒 ≤35 字、15 秒 40–55 字）
- 单条超过 15 秒：按 `references/long-video.md` 做分段规划，本阶段产出分段骨架
- 默认会切镜；要一镜到底必须明说，并保持全文一段情节描述

**决策点**：每个 shot 是否有明确职责（建立 / 动作 / 情绪 / 收尾）；职责模糊的 shot 重写。

## 5. 提示词构建

**目标**：按 `references/prompt-craft.md` 三段公式 + `references/prompt-templates.md` 模板生成提示词。

- 完整提示词 = 参考素材说明 + 核心创意 + 画面过程说明
- 注意：`prompt-craft.md` 中的“本流水线”指三段式快速路径；该快速路径无参考素材上传时跳过素材段。其他 workflow 按实际输入能力编写素材段
- 每段写齐六项：景别 + 内容 + 运镜 + 动作 + 台词 + 音效
- 台词必须给出原文，字数和时长对齐
- 不想要背景音乐时显式写：`非叙事性音乐：N/A`
- 提示词上限 7000 字符，超限先删词再拆镜
- 提交前逐条过踩坑表：分段了吗 / 素材用途说明了吗 / 音乐与 BGM 是否矛盾 / 一镜到底是否保持一段情节 / 主体外观是否具体 / 风格是否锁定

**确认点**：提示词定稿后向用户展示，尤其确认台词、画面文字、禁止项。

## 6. 执行

**目标**：选择 ComfyUI 工作流并提交生成。

选择工作流：

- 插件根模板 `assets/workflow_api_mzsj_video.json`：三段式快速路径
- 精选库 `examples/workflows/`：`video/` 视频生成与动作迁移、`first-frame/` 首帧与文生图、`upscale/` 放大修复、`product/` 人物一致性与产品场景
- 工作流选择依据见 `references/comfyui-workflows.md`

执行面事实：

- 提交 API 格式 workflow JSON 到 `POST /prompt`，得到 `prompt_id`
- 轮询 `GET /history/<prompt_id>`
- 产物在 `~/ComfyUI-Installs/ComfyUI/ComfyUI/output`（图片 `huoshen_*.png`，视频 `mzsj/*.mp4`）
- 自定义节点：`comfyui-mzsj-api`（DeepSeekPromptEnhance 提示词增强、MzsjVideoGenerate 视频生成）、`comfyui-huoshen-image`（HuoshenImageGenerate 首帧生图）
- API key 在各节点 `config.json`（仓库只带 `config.json.example`，密钥不入库）

快速路径脚本：

```bash
bash skills/ai-video-studio/scripts/make-video.sh "提示词" \
  --duration 5 --resolution 720p --size 1536x1024 --no-open
# 参数：--duration / --resolution / --size / --no-open / --dry-run
# --size 是首帧像素尺寸（如竖屏可用 1024x1536），不是画幅比例
# 退出码：0 成功，2 服务拉起失败，3 执行错误，4 超时
# 服务未启动时脚本会自动拉起本机 ComfyUI
```

任意 API 格式 workflow 使用通用 runner；先 dry-run，再提交：

```bash
python3 skills/ai-video-studio/scripts/run-workflow.py \
  <workflow.json> --project <项目目录> \
  --set '节点ID.inputs.字段="值"' --dry-run
```

去掉 `--dry-run` 后会提交并把实际 `workflow.json`、`history.json`、`run.json`
保存到 `<项目目录>/runs/<run-name>/`。字段路径必须以所选 workflow 的真实 JSON 为准。

批量纪律：

- 先批量生成首帧/镜头素材，验收通过后，再批量生成视频
- 不逐个镜头交替“生图 → 视频 → 生图 → 视频”
- 视频是高成本操作：每个视频生成前向用户确认

**决策点**：工作流是否匹配目标（文生 / 首帧 / 放大 / 产品）；高成本提交前是否已确认。

## 7. 验收迭代

**目标**：按 `references/quality-control.md` 两层 QC 验收，控制返工。

- 第一层：内容符合（主体、场景、动作、台词、禁止项）
- 第二层：质量达标（画质、音质、连贯性、时长）
- 一次只改一个变量；改完先看差异再决定下一步
- 同一镜头连续失败 ≥3 次：停下，向用户询问方向，不要无限重抽

**决策点**：问题属于提示词、工作流还是创意；只改对应变量。

## 8. 交付归档

**目标**：让产物可查、资产可复用、经验可沉淀。

- 输出命名：`项目-镜头-版本`（如 `coffee-project-scene03-v2.mp4`）
- 记录产物路径、参数、提示词版本到项目清单
- 可复用素材按 `references/asset-management.md` 入库
- 有价值的纠错与流程改动沉淀到 `references/skill-evolution.md`

**确认点**：最终交付物与 brief 逐项对照；改动经验是否值得写回 Skill。

## Agent 决策点与用户确认点

| 阶段 | Agent 决策点 | 用户确认点 |
| --- | --- | --- |
| 0 简报 | brief 是否完整 | 逐项打勾 |
| 1 调研 | 证据是否支撑结论 | 调研方向 |
| 2 创意 | 一句话创意与风格卡是否可执行 | 核心创意 |
| 3 资产 | 资产是否齐、可复用 | 资产清单与授权 |
| 4 剧本分镜 | shot 职责是否清晰 | 脚本与分镜 |
| 5 提示词 | 是否过踩坑表 | 台词/文字/禁止项 |
| 6 执行 | 工作流与批量策略 | 高成本生成前 |
| 7 验收 | 一次只改一个变量 | 失败 ≥3 次后的方向 |
| 8 归档 | 哪些入库、哪些沉淀 | 交付清单 |

## 失败处理策略

| 现象 | 先判断 | 处理 |
| --- | --- | --- |
| 内容不符、风格不对 | 提示词问题 | 回到第 5 步，按 `references/prompt-craft.md` 改 prompt，一次一个变量 |
| 提交报错、无产物、超时 | 执行问题 | 查 ComfyUI 服务与节点 `config.json`，按退出码定位；先 `--dry-run` 校验参数 |
| 越做越偏离目标 | 目标漂移 | 回到第 0 步重读 brief，确认后再继续 |
| 时长/节奏不对 | 规划问题 | 回第 4 步；超 15 秒走 `references/long-video.md` |

## 能力边界

能力边界按“默认打包节点”与“Studio 层”分层：

- 默认打包节点（快速路径）未实现：素材上传、图/视频/音频多模态参考、首 + 尾帧参考、
  视频/音频精准编辑、单次生成长视频；不要把这些边界扩大成整个 Studio 的能力边界
- Studio 层：本机 ComfyUI 可加载任意已安装节点与工作流，参考/首尾帧/精准编辑
  若由扩展节点提供，按该工作流实际能力执行；提交前以 `object_info` 实际加载为准
- 长视频 = 分段生成 + Agent 用 FFmpeg/剪辑工具拼接（工具可用性以本机环境为准），
  也可交给用户剪辑工具；本技能默认不内置自动拼接脚本
- 上游模型宣称具备多模态参考与精准编辑，但默认快速路径未实现，只可作为未来能力方向
  或提示词创作参考

## 30 秒种草片最小走查

目标：便携咖啡机 30 秒种草视频，9:16 竖屏。超过 15 秒，因此走分段规划。

| 阶段 | 一句话示例 |
| --- | --- |
| 0 简报 | 城市通勤打工人，小红书 9:16 种草，必须出现机身与压粉细节，禁止夸张功效词 |
| 1 调研 | 3 条同类内容，记录“痛点开场 → 使用过程 → 结果”结构 |
| 2 创意 | 清晨办公室，打工人 30 秒做出一杯热美式，写实生活方式广告 |
| 3 资产 | 复用资产中心的产品图与场景资产，登记咖啡机、办公桌、咖啡杯 |
| 4 剧本分镜 | 钩子 0–6s + 过程 6–20s + 结果 20–30s，每段 1–2 个 shot，台词按 3–4 字/秒分配 |
| 5 提示词 | 三段公式 + 模板，先过踩坑表再提交 |
| 6 执行 | 先批量生成 3 段首帧，逐段验收后生成视频；每段 ≤15 秒 |
| 7 验收 | 两层 QC，一次改一个变量 |
| 8 归档 | 命名 `coffee-project-scene03-v2.mp4`，记录路径并入库 |
