# 质量控制

何时加载：提交生成前、拿到生成结果后、失败重试前、向用户交付前。

## 一、两层 QC

QC 分两层，两层都要做，不能只查一边：

1. 提交前 QC：确认提示词与参数没有已知坑。
2. 结果验收 QC：确认产出在技术、内容、合规上达标。

## 二、提交前 QC（对照 prompt-craft 踩坑表）

| 检查项 | 判定规则 |
|---|---|
| 素材用途 | workflow 有素材输入时逐个写清用途；没有素材输入时跳过参考素材段 |
| 三段公式 | 核心创意（主体+地点+事件+题材风格）+ 画面过程（景别/内容/运镜/动作/台词/音效） |
| 正向描述 | 少写比喻与负向词；要禁止的写期望状态 |
| 介质锁定 | 末尾写 `Medium: <one primary medium>` |
| 台词预算 | 中文 3–4 字/秒：5 秒 ≤18 字、10 秒 ≤35 字、15 秒 40–55 字 |
| 文字原文 | 具体文字/Logo/标语写原文，如 `标题："AI Video Creation"` |
| BGM 声明 | 不要背景音乐时显式写 `非叙事性音乐：N/A`；环境音白名单式列出 |

提交前先过 `prompt-craft.md` 第三节踩坑表；模板直接抄 `prompt-templates.md`。

## 三、结果技术 QC

拿到产物后逐项查：

| 检查项 | 标准/动作 |
|---|---|
| 时长 | 上游约束 4–15 秒；与请求 `duration` 一致 |
| 分辨率/画幅 | 与请求 `--resolution`、`--size` 一致 |
| 帧率 | 24 FPS |
| 文件完整 | 路径存在、大小 >0、可正常打开 |
| 画面异常 | 无闪烁、黑帧、形变、穿模、文字乱码、画面截断 |
| 声音 | 有音轨、音量正常、环境音符合白名单、无意外 BGM |
| 台词/口型 | 台词量与预算匹配，口型不明显错位 |

技术检查命令：

```bash
ffprobe -v error -show_entries format=duration,size -of default=nw=1 output.mp4
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate -of default=nw=1 output.mp4
```

声音专项 QC：
- 有音轨：检查文件带音频流，没有则视为不合格。
- 音量：无明显过大削波或几乎无声。
- 环境音：只出现提示词白名单内的声音；意外鸣笛、人声、电话等视为异常。
- BGM：要求无 BGM 时不得出现音乐；有音乐需求时确认与画面节奏匹配。
- 台词与口型：预算内台词应能自然念完；明显念不完或口型错位要记录。

常见画面异常与处置：

| 异常 | 可能原因 | 处置 |
|---|---|---|
| 黑帧/闪烁 | 提示词画面过程不连贯 | 重写起始帧描述，先稳定开场再演进 |
| 形变/穿模 | 动作演进写得太跳跃 | 拆小动作步骤，明确"从该画面开始" |
| 文字乱码 | 未给原文或文字在画面里 | 把原文写进提示词，必要时用文字参考图 |
| 截断 | 内容超出时长预算 | 删减镜头或缩短台词 |

## 四、内容 QC

| 检查项 | 判定规则 |
|---|---|
| brief 满足度 | 必含元素都在、必不含元素都没有 |
| 主体一致性 | 脸、发型、服装、道具与参考/描述一致 |
| 风格与色彩 | 与目标风格包、色板一致 |
| 品牌元素 | Logo、名称、产品细节正确无变形 |
| 叙事节奏 | 时间轴/镜头顺序符合脚本 |
| 合规 | 人物肖像、版权、敏感内容；用户提供授权 |

内容 QC 必须留证据：把 brief 的必含/必不含清单与成片逐条对照，不合格项写进迭代记录，不要凭印象通过。

## 五、证据化迭代

失败不裸重试，先留证据：

```markdown
日期：2026-08-08
任务：镜头03 文生视频
失败路径：~/ComfyUI-Installs/ComfyUI/ComfyUI/output/mzsj/xxx.mp4
现象：脸部漂移、结尾黑帧
已改参数：prompt 增加人物外貌清单；duration 保持 5
结果对比：v2 脸部稳定，黑帧仍存在
```

迭代纪律：
- 一次只改一个变量（提示词、时长、分辨率，任选其一）。
- 同一参数失败 ≥3 次：停下，向用户询问或换策略，不继续烧钱。
- 不重复提交相同任务；同参数同内容重发不产生新信息。
- 每轮对比都要有失败路径、现象、已改参数、结果四要素。

## 六、验收标准

以客户当前有效要求、`decisions.md` 和本次产物的用途为“完成”定义。只有项目确实建立了镜头表时，
才把镜头数、连续性和每镜职责作为额外验收条件。

输出文件命名：`项目-镜头-版本`，示例：

```text
brand-02-v1.mp4
brand-02-v2.mp4
```

- 每次重生成递增版本，不覆盖已交付文件。
- 通过验收的成片归档（按 `asset-management.md` 大文件处理），交付时附检查结果。

## 七、沉淀

反复出现的问题与解法写入迭代记录：

- 问题 → 解法适合所有项目的，写进 `prompt-craft.md` 的踩坑表/失败模式表。
- 属于流程或策略演进的，写进 `skill-evolution.md` 的迭代记录。
- 沉淀时保留可复现样例与"改了什么参数有效"。

## 八、能力边界

默认打包节点没有自动修片/精准编辑能力（无背景替换、局部修改、台词替换等）。
画面小瑕疵的修复方式：重写提示词重新生成，或用 FFmpeg/剪辑工具做确定性修复。
多模态参考、首+尾帧、精准编辑若由已安装扩展节点提供，按实际能力执行；未提供时
交付前明确说明，不承诺做不到的效果。

## 九、自查清单

提交前：
- [ ] 三段公式齐全、台词预算合规
- [ ] 文字原文与 BGM 声明已写
- [ ] 参数合法（时长 4–15、分辨率/尺寸匹配）

结果验收：
- [ ] 技术指标逐项通过（时长/分辨率/帧率/声音）
- [ ] 内容与 brief 必含/必不含一致
- [ ] 合规确认（肖像/版权/敏感）
- [ ] 失败已留证据，一次只改一个变量
- [ ] 文件命名 `项目-镜头-版本`，重试递增版本
- [ ] 交付前与用户确认完成定义
