# 从视频实践演进 Skill

> 客户要求保存流程，或相同任务/纠错反复出现时读取。

Skill 保存 Agent 做好一类视频任务所需的非显然知识，不实现 Agent，也不把某个项目的内容、当前
实例限制或模型营销声明写成通用真理。

## 何时值得沉淀

满足任一强信号即可生成草稿：

- 客户明确要求保存本次方法；
- 同类任务重复出现，步骤和判断有稳定复用价值；
- 客户反复纠正同一种错误；
- 某个 workflow/外部服务需要不显然的可靠操作纪律；
- 成功结果依赖一组可解释的审美或连续性规则。

一次性的简单操作、具体台词、单个文件路径和偶然参数不应升级成 Skill。

## 捕捉什么

- 触发场景和不适用边界；
- 输入、可见产物和交付；
- 客户在哪些地方需要看见结果再决定；
- 成功判断、失败表现、局部修复和停止条件；
- 资产如何传递、什么产生什么；
- 哪些机械操作值得放进确定性脚本；
- 哪些实例/外部服务配置事实应留在配置，而非 Skill。

## 创建与更新

1. 从 `decisions.md`、`assets.md`、实际 workflow/run 和客户反馈提炼规则。
2. 先生成草稿，删除单项目内容、密钥、临时 URL 和未验证能力。
3. 使用宿主已安装的 `skill-creator` 决定 SKILL/references/scripts 分层并验证。
4. 用新的真实任务做前向测试，避免只复述原案例。
5. 安装、覆盖或大幅修改正式 Skill 前告知客户。

不要在这里重复通用 Skill 创建教程，也不要用脚本自动判断创意经验是否值得沉淀。Agent 负责语义
判断，`skill-creator` 负责结构规范，客户保留最终控制权。

## 本项目的边界

- `SKILL.md` 保持平台中立；Codex/Qoder 等宿主映射放独立 reference。
- workflow 技术步骤属于 workflow manifest/实例配置，不复制进每个生产 Skill。
- 外部资料只做创造性转化；许可或来源不清的原文保存在本地研究区，不随插件发布。
- 验证状态必须区分 `untested`、`dry-run`、`live-tested`。
