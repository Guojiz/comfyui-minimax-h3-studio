# 局部返工与回滚

> 比较候选、修改局部、恢复旧版本或生成失败时读取。

## 单一事实来源

`assets.md` 记录产物状态、来源和采用关系；`runs/` 保存客观执行证据。不要用共享输出目录的“最新
文件”判断版本，也不要让失败迭代覆盖已批准资产。

每个新版本使用新路径和稳定 ID；需要时给 runner 传 `--shot`、`--iteration` 关联执行记录。这两个
字段是辅助留痕，不是所有项目都必须先建立镜头状态机。

## 只重算受影响部分

| 问题 | 回退位置 | 保留内容 |
| --- | --- | --- |
| 创意方向不合适 | 更低成本方向产物 | 原素材、客户否决记录、可复用技术成果 |
| prompt/动作不符 | prompt | 资产、其他已通过产物、旧候选 |
| 首帧/参考素材错误 | 对应资产 | 未受影响资产和脚本 |
| workflow/外部服务失败 | 技术执行层 | 创意、prompt、素材 |
| 字幕、响度、转场 | 后期 | 所有生成镜头 |

一次只改变一个主要变量。新结果先标为 `candidate`；通过后更新为 `approved`，未通过则保留旧最佳
候选。回滚只修改 `assets.md` 中的采用关系和状态，不删除文件。

连续失败 3 次、预算耗尽、整体目标漂移或需要新授权时停止并请求客户决策。
