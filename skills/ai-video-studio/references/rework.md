# 镜头状态与局部返工

> 何时加载：生成多个镜头、比较版本、QC 不通过、需要回滚或只重做局部时。

## 单一事实来源

使用项目 `shots/index.md` 记录每个镜头的状态、最佳 run 和下一步。`runs/` 保存不可变执行证据，
不要用共享输出目录的“最新文件”判断版本。

状态流转：

`planned → prompt_ready → generated → qc_pass / qc_rework → final`

## 提交与版本

每次提交都带镜头和迭代：

```bash
python3 scripts/run-workflow.py workflow.json \
  --project <project> --shot s03 --iteration v2
```

- `shot_id` 在项目内稳定，不因重做改变。
- `iteration` 每次生成递增，旧 run 不覆盖、不删除。
- `best_run` 只指向当前最优版本，不等于最新版本。
- 比较版本时记录“改了什么、改善了什么、退化了什么”。

## 返工决策

先判断问题属于哪一层，只重算受影响节点及下游：

| 问题 | 回退位置 | 保留内容 |
| --- | --- | --- |
| 提示词内容/动作不符 | prompt | 资产、其他镜头、已通过 run |
| 首帧或参考素材错误 | 资产/首帧 | 脚本、未受影响镜头 |
| workflow/节点失败 | 执行层 | 创意、prompt、素材 |
| 字幕、响度、转场 | 后期 | 所有生成镜头 |
| 整体方向错误 | 方向与 shot 表 | 原始素材和失败证据 |

一次只改变一个主要变量。结果通过则更新 `best_run`；不通过则保留旧最佳版本。连续失败 3 次、
预算耗尽或必须改变整体方向时停止并请求用户决策。

## 回滚

回滚只修改 `best_run` 指针与镜头状态，不删除新旧文件。合成始终读取 `best_run`，因此任何一次
失败迭代都不会污染已通过镜头或最终时间线。
